## unalloc 0.3.0

This release makes a report rebuildable. **Attribution results are unchanged**: every report from 0.2.3 gives the same numbers.

```bash
pip install --upgrade unalloc
```

### Why

A percentage quoted in a finance review gets questioned weeks later, after the data behind it has moved. A file path doesn't settle that: an export can be rewritten under the same name, and a live billing API answers a re-run with today's numbers. 0.2.3 also had a quieter gap. When a live source failed, it was printed to stderr and dropped, and the JSON gave no sign that its percentage covered only some of the sources.

### What's new

- **Provenance in `report --json`:** unalloc version, window, alias-table digest, and per source its status (`loaded`, `missing` or `failed`), payload SHA-256 and row count, plus a digest of the result.
- **`--keep-inputs DIR`:** keeps the exact payloads the run parsed, so it can be replayed offline.
- **`unalloc verify RESULT --inputs DIR`:** rebuilds the report and exits 0 (reproduced), 3 (an input is missing or changed), 4 (same inputs, different result: a rule or the tool changed), or 5 (the recorded result does not conserve its own total).
- **Partial-ledger warnings:** every command names each source that didn't load.

```bash
unalloc report -D team --json --keep-inputs runs/2026-09/ > runs/2026-09.json
unalloc verify runs/2026-09.json --inputs runs/2026-09/
```

A digest proves byte identity, not correctness. It cannot show a meter was accurate or a rule fair, and it can only rebuild a result when the bytes it names were kept.

### Fixed

- With a missing fixture, `report --json` printed a notice to stdout and produced invalid JSON. The notice now goes to stderr.
