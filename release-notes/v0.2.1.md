## unalloc 0.2.1

This release adds a real-GPU validation of the case-study results and prepares the accompanying paper for arXiv. **The CLI's behaviour is unchanged from 0.2.0**; if you only use `unalloc` itself, upgrading changes nothing but the version number.

```bash
pip install --upgrade unalloc
```

### Validated on an NVIDIA H100

The metering experiments from 0.2.0 ran on a CPU and in a simulator. This release re-runs them with production serving software on a datacenter GPU:

- **Setup:** vLLM 0.29.0 serving Qwen2.5-7B-Instruct on one H100 80GB (a DigitalOcean GPU Droplet), driven with the simulator's four tenants at 2, 4, 8 and 16 requests/s. 6,241 requests, 0 errors.
- **The meters still disagree.** A token meter assigns the retrieval-heavy tenant 12–14 percentage points more of the bill than an equal time-share meter, at every load tested.
- **GPU utilization is not a cost signal.** `nvidia-smi` read 97–99% from 2 to 16 requests/s while throughput rose 7×; power draw (469 W → 660 W) tracked load.
- **Latency:** median time to first token 26–51 ms, median time per output token 6.3–12.2 ms.
- **The simulator was too pessimistic.** Its latency model saturates at 8 requests/s; the H100 handled 16 with nothing queued. Its bill shares agree in direction, but its latencies are uncalibrated.

Everything is reproducible from the repository: `case_studies/gpu_validation/` holds the benchmark client, a fake server for free dry runs, the remote setup script and the analysis. `RUNBOOK.md` walks through bring-up, verification and teardown on DigitalOcean. The raw data and the captured terminal output of every step, from droplet creation to a verified deletion, are committed under `case_studies/results/gpu_validation/`. The whole run cost about $2.15.

### Paper

`unalloc-case-studies.pdf` (attached) is revised for submission:

- A new section, "Validation on a datacenter GPU", with the H100 results.
- The abstract now leads with the attribution failures found where Kubernetes, gateway and provider ledgers meet: owner labels missing from worker pods, fallback labels resolving to a Helm chart name, double counting, and truncated billing reads.
- Metering results are stated as disagreement between rules rather than over-charging, since none of the rules compared is a ground truth.
- A new Related Work section, including recent Shapley-based energy attribution for batched LLM serving.
- The list of defects fixed in 0.2.0 moved to an appendix, and a statement on the use of AI tools was added.

### Also in this release

- `paper/build.py` now refuses to build when the Typst source contains constructs that compile but render wrong. The 0.2.0 PDF was affected: six approximate figures lost their "~" sign, for example "(~25% of spend)" printed as "( 25% of spend)". This release's PDF is corrected.
- A blog addendum with the GPU specs, results and evidence images (`blog/addendum-gpu-validation.md`).
- Tests for the GPU validation pipeline's metrics parsing, trace generation and meters.
